<Section label="03 · Why" title="Industrial data should not stay trapped">
  <p>There is enormous potential in connecting the devices that run our factories, grids and buildings. Energy shows it most clearly: a sustainable, decentralized grid only works when solar inverters, batteries, meters and substations exchange data reliably.</p>
  <p>Yet that data is locked inside PLCs, RTUs, meters, inverters and building controllers. Every device speaks its own protocol, documentation is often incomplete, and integrations are rebuilt from scratch for every site and vendor. We think the foundation for industrial connectivity should be open, well tested and reusable, so that nobody has to solve the same protocol problem twice.</p>
</Section>

<Section label="04 · How we build" title="Built with AI agents">
  <p>OT Fabric is built by people and AI agents working together. We are heading toward a reality where LLMs write better code and deliver more secure software, and we build for that reality today. Engineers bring the domain knowledge of real OT systems, set direction and own every decision. Agents bring speed, breadth and attention to detail.</p>
  <p>Speed alone is not the goal. Industrial protocols leave no room for "mostly works", so everything we ship is held to the same bar: public code, public tests and [interoperability suites](/projects/#interop) that check it against other implementations.</p>
</Section>
