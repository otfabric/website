`nsdctl` is the command-line tool included with [go-iec61850-model](/projects/go-iec61850-model/). It answers integration questions from the official IEC 61850 information model embedded in it, with no download or setup, and works on NSD packages you obtained yourself. It does not talk to devices: for that, use [iec61850ctl](/docs/protocols/iec-61850/cli/).

## Install

<InstallTool tool="nsdctl" />

`nsdctl completion bash|zsh|fish|powershell` prints a shell completion script.

## What a logical node holds

```sh
nsdctl model show MMXU            # every data object, inherited ones included, with CDC and presence
nsdctl model measurements MMXU    # what each measurement means, per phase, with the expected unit
nsdctl model leaves MMXU.TotW --fc MX
```

The last command lists the attributes a client reads for total active power (output from the go-iec61850-model use cases):

```text
PATH                 TYPE       KIND        FC
MMXU.TotW.instMag.i  INT32      BASIC       MX
MMXU.TotW.instMag.f  FLOAT32    BASIC       MX
MMXU.TotW.mag.i      INT32      BASIC       MX
MMXU.TotW.mag.f      FLOAT32    BASIC       MX
MMXU.TotW.range      RangeKind  ENUMERATED  MX
MMXU.TotW.q          Quality    BASIC       MX
MMXU.TotW.t          Timestamp  BASIC       MX
```

## Does an instance satisfy the model

```sh
nsdctl model check XCBR --present Beh,Loc,OpCnt,Pos,BlkOpn,BlkCls,CBOpCap --value Pos.ctlModel=sbo-with-normal-security
nsdctl model check --scl device.cid --ln LD0/XCBR1
```

`model check` evaluates the presence conditions of one logical node instance, given as a list of data objects, a JSON instance or a logical node of an SCL file. Each element is required, optional or forbidden, and satisfied, violated or undetermined, with the reason; a condition that needs a fact the instance does not give stays undetermined and names it (`--fact`). It exits with code 1 when a condition is violated, so it fits a CI check of SCL files. `nsdctl validate --presence` checks the conditions of a namespace itself.

## What a reference means

```sh
nsdctl model describe 'LD0/MMXU1.PhV.phsA.cVal.mag.f[MX]'
nsdctl model show 'LD0/MMXU1.PhV.phsA.cVal.mag.f[MX]'
```

`describe` prints the semantic descriptor (voltage, phase A, line to ground, magnitude, expected in V) with the rule it came from. `show` resolves the reference step by step, with the type, functional constraint, presence and declaring namespace of every element. A reference the model does not define fails with exit code 1 and names the element that is wrong. Quote references in shells that glob brackets, such as zsh.

## Decode raw values

```sh
nsdctl model show SIUnitKind        # 38 is W
nsdctl model show MultiplierKind    # 3 is k
nsdctl model show BehaviourModeKind # 5 is off
```

## Two namespaces, one name

```sh
nsdctl -p extended model show DBAT --ns 90-9
nsdctl catalog overlaps --left IEC_61850-7-420 --right IEC_TR_61850-90-9
```

Without `--ns`, a name that two namespaces of the profile define fails as ambiguous. `catalog overlaps` classifies every shared name as identical, a compatible extension or conflicting.

## The release a device declares

```sh
nsdctl catalog select "IEC 61850-7-4:2007A"       # the embedded profile for a device's LLN0.NamPlt.ldNs
nsdctl -p edition2 model show MMXU
nsdctl -p "IEC 61850-7-4:2007B4" model show XCBR   # any embedded release, by its ID
```

The embedded catalog holds every NSD release IEC publishes (28 namespaces since go-iec61850-model v0.8.0; nsdctl uses it since v0.8.1), so an older device is looked up against the release it was configured for, not the newest one. IEC publishes no NSD for Edition 1 (2003) of 7-4.

## Work with NSD packages

```sh
nsdctl sources fetch                         # official packages into .nsd-cache/, digests verified
nsdctl sources check --packages .nsd-cache   # coverage of the tracked packages
nsdctl validate .nsd-cache
nsdctl -s .nsd-cache model show MMXU
nsdctl diff --exit-code ./old/ ./new/
nsdctl -s .nsd-cache generate go -o .generated/go --package iec61850names
```

Without `--source` (`-s`), the `model` and `catalog` commands use the embedded catalog; `-p` selects a named profile (`default`, `extended`, `edition2`) or any embedded namespace release. Apart from `sources fetch`, nsdctl never downloads anything. Output generated from NSD packages stays local unless the lock file permits publishing it.

## Output and exit codes

Every command prints text, or JSON with `--json`, so the model can feed scripts, tag lists and UIs directly.

Since go-iec61850-model v0.3.0 nsdctl uses the organisation's exit codes:

| Code | Meaning |
|---|---|
| 0 | OK |
| 1 | Findings: `validate` found errors, `dependencies` found unsatisfied dependencies, or differences (`diff --exit-code`, `generate --check`, `sources check`, `schema --exit-code`) |
| 2 | Usage error, a name the model does not define, a path that does not resolve, a refused overwrite |
| 3 | A source cannot be read or parsed; an invalid lock or registry, a load error, a digest mismatch or an unpinned package |
| 4 | A download of `sources fetch` failed |
| 9 | Refused by the licence policy (`generate --publish`) |
| 10 | Writing the output failed, or an unexpected error |
| 130 | Interrupted (SIGINT or SIGTERM) |

Before v0.3.0, usage errors were 1, source errors 2, validation errors 3, differences 4 and a licence refusal 5; scripts that test the codes need the new values.
