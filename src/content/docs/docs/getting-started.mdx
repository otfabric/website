OT Fabric is an open-source ecosystem for industrial connectivity and interoperability. It gives the people who build, operate and integrate industrial systems one consistent toolkit across the protocols that run factories, grids, buildings and EV charging: Modbus, OPC UA, BACnet/IP, IEC 60870-5-104, IEC 61850 (MMS, GOOSE and Sampled Values), Siemens S7, OpenADR, OCPP, DNP3, IEEE 2030.5, EtherNet/IP, PROFINET, CANopen with the CAN bus it runs on, and KNX, the information models carried over them, SunSpec Modbus and the IEC 61850 information model, and Sparkplug B, the industrial messaging profile for MQTT.

Everything is MIT-licensed and public on GitHub, built by people and AI agents together, and the protocol stacks are proven against independent implementations, not only against their own tests.

## What the ecosystem covers

| Part | What it gives you | Examples |
|---|---|---|
| **Protocol libraries** | Client and server implementations to embed in gateways, services and products. Pure Go, no cgo | [go-modbus](/projects/go-modbus/), [go-opcua](/projects/go-opcua/), [go-ocpp](/projects/go-ocpp/), [go-dnp3](/projects/go-dnp3/), [go-ieee20305](/projects/go-ieee20305/), [go-ethernetip](/projects/go-ethernetip/), [go-profinet](/projects/go-profinet/), [go-canopen](/projects/go-canopen/), [go-knx](/projects/go-knx/) on [go-canbus](/projects/go-canbus/) |
| **Information-model libraries** | Standard device and data models on top of a protocol: discovery, decoding, validation and serving | [go-sunspec](/projects/go-sunspec/), [go-iec61850-model](/projects/go-iec61850-model/) |
| **Application-profile libraries** | How a protocol is used for one interoperable application: topic namespaces, payloads and session state | [go-sparkplugb](/projects/go-sparkplugb/) |
| **Command-line tools** | One tool per protocol to discover, read, write, monitor, simulate and diagnose devices in the field, with JSON output for scripts and CI | [modbusctl](/projects/modbusctl/), [opcuactl](/projects/opcuactl/), [openadrctl](/projects/openadrctl/), [ocppctl](/projects/ocppctl/), [dnp3ctl](/projects/dnp3ctl/), [ieee20305ctl](/projects/ieee20305ctl/), [ethernetipctl](/projects/ethernetipctl/), [profinetctl](/projects/profinetctl/), [canbusctl](/projects/canbusctl/), [canopenctl](/projects/canopenctl/), [knxctl](/projects/knxctl/), [sparkplugbctl](/projects/sparkplugbctl/) |
| **Interoperability suites** | Independent reference stacks in containers behind one contract, so any implementation, ours or yours, can be tested against the established ones | [modbus-interop](/projects/modbus-interop/), [iec61850-interop](/projects/iec61850-interop/), [ocpp-interop](/projects/ocpp-interop/), [dnp3-interop](/projects/dnp3-interop/), [ieee20305-interop](/projects/ieee20305-interop/), [ethernetip-interop](/projects/ethernetip-interop/), [profinet-interop](/projects/profinet-interop/), [canbus-interop](/projects/canbus-interop/), [canopen-interop](/projects/canopen-interop/), [knx-interop](/projects/knx-interop/), [sparkplugb-interop](/projects/sparkplugb-interop/) |
| **Network visibility** | What is connected to an OT network, what changed, which protocols it speaks and which devices answer | [LAN Tracker](/projects/lan-tracker/), [otprobe](/projects/otprobe/), [go-otfp](/projects/go-otfp/) |
| **Desktop apps** | Graphical tools for engineers, integrators and commissioning teams | [SunSpec Explorer](/projects/sunspec-explorer/), [Modbus Trace Explorer](/projects/modbus-trace-explorer/) |
| **Captures and simulation** | Record real devices, serve them again as virtual devices, and read packet traces offline | [MBCAP](/projects/go-modbus-capture/), [modbus-simulator](/projects/modbus-simulator/), [go-modbus-trace](/projects/go-modbus-trace/) |
| **Ecosystem map** | An open, source-backed registry of more than a hundred open-source and commercial protocol stacks, with licence, roles and latest release | [Ecosystem map](/ecosystem/implementations/) |

Shared building blocks such as [go-serial](/projects/go-serial/), [go-tpkt](/projects/go-tpkt/) and [go-cotp](/projects/go-cotp/) sit underneath. Each protocol ships the same way: a library, a command-line tool where field work needs one, an interop suite where independent stacks exist, and documentation that explains how the protocol works before it explains the code.

### Where it is heading

The roadmap is full coverage of the OT protocols that matter, **IT-to-OT gateways and data connectors** that move industrial data safely into IT, cloud and analytics systems, and **OT MCP servers** that let AI agents discover, read and work with industrial devices under the same safety rules as a person. [About OT Fabric](/about/) has the why.

## Pick your path

<Tabs>
  <TabItem label="I want to look at a device">
    Download the CLI for your protocol from its GitHub Releases page. Binaries are available for Linux (x86-64, ARM64, ARMv7), macOS and Windows, with SHA-256 checksums. No Go toolchain is needed.

    ```sh
    # Example: what is this Modbus device?
    modbusctl client identify --ip 192.168.1.10 --server-id
    ```
  </TabItem>
  <TabItem label="I want to write code">
    Add the library to a Go module:

    ```sh
    go get github.com/otfabric/go-modbus
    ```

    Each protocol page has a short, complete example to start from.
  </TabItem>
  <TabItem label="I want to test my own stack">
    The interop suites do not depend on OT Fabric code, so any implementation in any language can use them. Start a reference server from its image, point your client at it, and ask each image what it supports:

    ```sh
    docker run --rm ghcr.io/otfabric/modbus-interop-libmodbus:<tag> print-capabilities
    ```

    Each protocol's *Testing and interop* page lists the images, fixtures and commands.
  </TabItem>
  <TabItem label="I want to see my network">
    [LAN Tracker](/projects/lan-tracker/) keeps a history of what is connected to your OT networks: which MAC held which IP and when, names, DHCP leases, reachability and duplicate addresses. It is passive by default. Download it from its [GitHub Releases](https://github.com/otfabric/lan-tracker/releases).
  </TabItem>
</Tabs>

<Aside type="caution" title="Use on equipment you are authorized to test">
These tools send real requests to real equipment. Start with read-only commands, and try writes against a simulator before you connect to a live PLC, RTU or controller.
</Aside>
