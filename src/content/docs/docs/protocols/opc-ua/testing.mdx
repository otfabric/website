OT Fabric tests its OPC UA implementation against six independent stacks rather than only against itself. [opcua-interop](https://github.com/otfabric/opcua-interop) packages the reference stacks as Docker images; [go-opcua](https://github.com/otfabric/go-opcua) owns the test cases and the published compatibility claims. This page describes opcua-interop v0.14.0 and go-opcua v1.23.1.

## Reference stacks

| Adapter | Language | Stack version | Notes |
|---|---|---|---|
| open62541 | C | open62541 v1.5.9, OpenSSL crypto backend, mDNS via mdnsd | ECC policies, reverse connect, LDS and mDNS, PubSub with MQTT and SKS, alarms, push management |
| Eclipse Milo | Java | Eclipse Milo v1.1.8 with `milo-encoding-json` and `milo-encoding-xml` | No ECC policy, no ReverseHello, not a discovery server, no PubSub |
| async-opcua | Rust | async-opcua 0.19.0, pure Rust crypto | No ECC, no LDS, no PubSub; trusts exact certificates only |
| UA-.NETStandard (`dotnet`) | C# | OPC Foundation UA-.NETStandard 2.0.1 on .NET 10 | The reference implementation: PubSub (UDP, MQTT, chunks, discovery), `opc.wss` and `opc.https`, alarms, push management |
| node-opcua | TypeScript | node-opcua 2.187.12 on Node.js 24 | Reverse connect, alarms, push management; no ECC, no node management served |
| opcua-asyncio (`asyncua`) | Python | opcua-asyncio 2.1.0 on CPython 3.14 | RSA policies only, no reverse connect, no PubSub |
| UA-.NETStandard GDS (`dotnet-gds`) | C# | UA-.NETStandard 1.5.378.182 GDS packages | Global Discovery Server and GDS pull client; a separate image because the GDS packages have no 2.0.x release |

The images are `ghcr.io/otfabric/opcua-interop-<adapter>:<version>` (`open62541`, `milo`, `async-opcua`, `dotnet`, `node-opcua`, `asyncua` and `dotnet-gds`), for linux/amd64 and linux/arm64. Tags are immutable, and go-opcua pins all seven by digest to v0.14.0.

Each image has the same modes: `server` (start a server from a fixture), `client` (run one probe operation), `test`, `validate-fixture` and `print-capabilities`. An Eclipse Mosquitto broker, pinned by digest, carries the MQTT PubSub tests.

## Using the reference servers as simulators

The reference servers are a safe target for the library and for opcuactl. They build a deterministic address space from a shared fixture, so both stacks expose the same nodes.

<Steps>

1. **Start a server.** From a checkout of opcua-interop (needs Docker with BuildKit, `make`, `jq`, and `openssl` 1.1 or later for certificates):

    ```sh
    make run-open62541   # open62541 server on port 4840
    make run-milo        # Milo server on port 4841
    make run-dotnet      # UA-.NETStandard server on port 4843
    make run-asyncua     # opcua-asyncio server on port 4845
    make run-dotnet-gds  # UA-.NETStandard Global Discovery Server on port 4846
    ```

2. **Probe it with the reference client.**

    ```sh
    docker run --rm --network host \
      ghcr.io/otfabric/opcua-interop-open62541:latest \
      client read \
      --endpoint opc.tcp://localhost:4840/opcua-interop \
      --node 'nsu=urn:otfabric:opcua-interop:model;s=Scalar.Int32'
    ```

    On macOS with Docker Desktop, use `--add-host=host.docker.internal:host-gateway` and `host.docker.internal` instead of `--network host`.

3. **Point your own client at it**, for example `opcuactl browse tree -e opc.tcp://localhost:4840/opcua-interop --depth 2`.

</Steps>

The baseline fixture lives under `Objects/Compatibility` in namespace `urn:otfabric:opcua-interop:model`. Always reference nodes by that namespace URI; the index differs between stacks.

| Folder | Content |
|---|---|
| Scalars | One read/write variable per built-in type, with values chosen to expose encoding errors |
| Arrays | Empty, one-element, multi-element, String, ByteString, 2D matrix |
| Dynamic | `Counter` (Int64, 250 ms), `Toggle` (Boolean, 500 ms), `Ramp` (Double, 100 ms) |
| Access | Read-write, read-only, write-only |
| Methods | `Add`, `Multiply`, `Echo`, `NoArguments`, `MultipleOutputs`, `Fail` |
| Events | `Events.Source` emits a BaseEvent about every 2 s, Severity 500 |
| History | `History.Temperature`: 5 raw samples |
| Analog | `Analog.Level`, `Analog.Setpoint`: AnalogItemType with EURange 0..100, for deadband tests |
| Alarms | `Alarms.InteropAlarm`, an alarm condition for the Alarms and Conditions tests (open62541, UA-.NETStandard and node-opcua servers) |
| PubSub | Writable variables of every common type for published fields and TargetVariables |

The fixture user is `test-user` / `test-password`; users with the SecurityAdmin role may call push certificate management. A secured server needs `--certificate`, `--private-key` and `--pki-dir`; the fixture's `securityProfiles` decide which secure endpoints are advertised.

<Aside type="caution" title="Test PKI only">
`make certs` generates a test CA and identities under `certs/test-pki/`, including ECC certificates per curve. These private keys are for isolated test environments. Never use them in production or expose them to untrusted networks.
</Aside>

Without opcua-interop, the go-opcua repository has runnable servers in `examples/server/node_server`, `map_server`, `NodeSet2_server` and `method_server`, a PubSub server in `examples/pubsub/server`, and a Global Discovery Server in `examples/gds-pull`.

## What each adapter supports

Run `print-capabilities` to see the client operations, client and server features, security profiles and codec support of an image:

```sh
docker run --rm ghcr.io/otfabric/opcua-interop-open62541:latest print-capabilities
docker run --rm ghcr.io/otfabric/opcua-interop-dotnet:latest print-capabilities
```

| Feature (v0.14.0) | open62541 | Milo | async-opcua | UA-.NETStandard | node-opcua | asyncua |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| DataChangeFilter, client and server | Yes | Yes | Yes | Yes | Yes | Client only |
| Reverse connect | Yes | No | Yes | Not wired | Yes | No |
| ECC security policies | Yes | No | No | No (refuses the test PKI's ECC certificates) | No | No |
| LDS server, mDNS | Yes | No | No | No | No | No |
| Node management served | Yes | No | Yes | Yes | No | Admin role only |
| Alarms and Conditions server fixture | Yes | No | No | Yes | Yes | No |
| Push certificate management server | Yes | No | No | Yes | Yes | No |
| `opc.wss` and `opc.https` | No | No | No | Yes | No | No |
| PubSub | UDP, MQTT, SKS, information model | No | No | UDP, MQTT, chunks, discovery | No | No |
| `codec` JSON / XML | Compact / partial | Compact and verbose / yes | No | Compact and verbose / yes | No | No |

The client mode has nineteen operations, among them `endpoints`, `read`, `write`, `browse`, `call`, `subscribe`, `event-subscribe`, `alarms`, `history-read`, `republish`, `transfer-subscriptions`, `node-management`, `register-server` and `codec`, plus `push` on node-opcua, `pubsub-discover` on UA-.NETStandard and `gds-pull` on dotnet-gds. All write JSON to stdout. `--channel-lifetime-ms` requests a short SecureChannel lifetime to force token renewals during a command.

## Running the go-opcua interop suite

The suite lives in go-opcua's `interop/` directory behind the `interop` build tag. Tests start and stop the containers themselves; no pre-running containers or manual steps are needed.

<Tabs>
  <TabItem label="Release images">
    ```sh
    # Test PKI for the security, ECC and secured reverse connect tests
    (cd ../opcua-interop && certs/generate.sh)
    export OPCUA_INTEROP_PKI_DIR=$PWD/../opcua-interop/certs/test-pki

    make interop

    # Release verification: fail instead of skip on any missing capability
    OPCUA_INTEROP_REQUIRE_CAPABILITIES=1 make interop
    ```
  </TabItem>
  <TabItem label="Local images">
    ```sh
    cd ../opcua-interop && make image-open62541 image-dotnet
    cd ../go-opcua
    OPEN62541_IMAGE=ghcr.io/otfabric/opcua-interop-open62541:dev \
    DOTNET_IMAGE=ghcr.io/otfabric/opcua-interop-dotnet:dev \
    make interop
    ```
  </TabItem>
</Tabs>

The mDNS tests create a user-defined Docker bridge network and cross-compile a go-opcua discovery server into a container, so the daemon must allow bridge networks and Go must be able to build for `GOOS=linux` with `CGO_ENABLED=0`. A go-opcua server in a container must be published on the same port it listens on.

Every capability is tested in both directions per peer: the go-opcua client against the peer's server, and the peer's client against the go-opcua server. A row is marked verified only when a named peer test ran against the pinned images without skipping; Go-to-Go tests never earn a verified mark. Every row a peer cannot pass carries its reason: the peer lacks the feature, deviates from the specification, or the adapter does not offer the command yet.

| Peer | Verified | Unverified | Unsupported by the peer | Deferred |
|---|---:|---:|---:|---:|
| open62541 and Eclipse Milo | 476 | 70 | 228 | 60 |
| async-opcua | 148 | 49 | 192 | 28 |
| UA-.NETStandard | 225 | 29 | 131 | 32 |
| node-opcua | 159 | 30 | 203 | 25 |
| opcua-asyncio | 123 | 34 | 228 | 32 |

The counts come from the ledgers in go-opcua's `interop/` directory (`COVERAGE.md` and `testdata/ledger-*.json`).

## What has been validated

Verified with every peer that has the feature, in both directions, among others:

- Reads of every built-in scalar type, arrays and matrices, batch reads, IndexRange, TimestampsToReturn, write and read-back, access-level rejections.
- Browse, BrowseNext, TranslateBrowsePaths, RegisterNodes; method calls with argument validation and Bad results.
- Subscriptions: queue windows, timestamps, publishing and monitoring modes, DataChangeFilter deadbands and triggers, Republish and TransferSubscriptions, recovery after a reconnect.
- Security: the RSA policies in Sign and SignAndEncrypt, trusted and untrusted certificates, valid and invalid usernames, SecureChannel renewal under a live subscription, multi-chunk secured messages.
- Event subscription with OfType and severity filters; raw HistoryRead and continuation points; LDS registration and FindServers.
- **Alarms and Conditions:** ConditionRefresh, Acknowledge, Confirm and AddComment in both directions with open62541, UA-.NETStandard and node-opcua, and from every peer client against the go-opcua server; the OPC UA 1.05 methods, dialogs, branches, alarm groups, timing, metrics and audit events from all six peer clients.
- **Certificate management:** the push model against open62541, UA-.NETStandard and node-opcua servers, with the node-opcua push client against the go-opcua server, and the 1.05 additions against UA-.NETStandard; the GDS pull model in both directions against the UA-.NETStandard Global Discovery Server.
- **Transports:** `opc.https` and `opc.wss` against UA-.NETStandard.
- **PubSub:** with open62541, UADP and JSON codecs byte for byte, UDP unicast and multicast, Ethernet, MQTT 3.1.1 and 5.0 through Mosquitto, message security, the SKS (pull and push) and the PublishSubscribe methods; with UA-.NETStandard, UDP, MQTT, static-key security, chunked NetworkMessages and UADP discovery. AMQP 1.0 is tested go-opcua to go-opcua through RabbitMQ 4 and ActiveMQ Artemis.
- **JSON and XML** encodings of values with open62541, Milo and UA-.NETStandard.

With open62541 only, because no other peer has the feature: all ECC policies including Brainpool and Curve448 (the AEAD and Brainpool policies in SignAndEncrypt only), username tokens and renewal over ECC, reverse connect including secured channels (also with async-opcua and node-opcua), and mDNS discovery.

Interop found go-opcua defects that Go-to-Go tests could not: the RSA-OAEP-SHA256 block size (UA-.NETStandard), the first sequence number of a channel (async-opcua), the renewal of a superseded token (asyncua) and in-place key swaps on renewal (open62541, Milo). The peers' own deviations, such as ignored TimestampsToReturn or writes with a SourceTimestamp accepted, are pinned by the tests and listed in go-opcua's [interop gaps](https://github.com/otfabric/go-opcua/blob/main/docs/interop-gaps.md).

## What has not been validated

- **Deferred:** NodeSet2 import, cross-stack custom DataTypes, IssuedIdentityToken, HistoryRead modified, at-time, processed and events and HistoryUpdate against peers, certificate chains and CRLs, custom event emission and the general WhereClause surface for peer clients, and secured LDS registration against a peer LDS.
- **Waiting for an adapter:** push management and GDS clients for open62541 and Milo, PubSub chunks, discovery and keyed codec operations in the open62541 adapter, and the 1.05 alarm conditions on a peer server.
- **ECC with other stacks:** open62541 is the only ECC peer; UA-.NETStandard 2.0.1 refuses the test PKI's ECC certificates. ECC `Sign` mode follows open62541 v1.5.9 and is not expected to interoperate with stacks that follow OPC UA 1.05.07.
- Not certified by the OPC Foundation.

## Other test layers

| Layer | Command | What it covers |
|---|---|---|
| Unit and race tests | `make test-norace`, `make test` | All packages; coverage gate of 90% on core packages |
| Conformance | part of `go test ./...` | The go-opcua client against an in-process server, per area: address space, subscriptions, sessions, security, transports, history, alarms, certificate management, discovery and PubSub; fails when an exported client method or option is exercised by none of them |
| Integration | `make integration`, `make selfintegration` | Go client against a FreeOpcUa Python server, and against an in-process Go server |
| Chaos | `make chaos` | Faults on unsecured and secured channels (bit flips, replayed, lost and reordered chunks), DataChangeFilter, reverse connect, discovery, codecs, certificate management, the GDS, and PubSub over lossy networks and failing brokers; seeds are logged for replay |
| Fuzzing | `ua`, `uasc`, `uacp`, PubSub and more | Binary, JSON and XML decoders, secure channel, transport, WebSocket and HTTPS, certificates and PFX files, mDNS, and the UADP, JSON, MQTT, AMQP and Ethernet parsers |

opcuactl has end-to-end tests that run the CLI against a go-opcua server, including alarms, certificate management and PubSub. Its published example outputs were captured against a WAGO 750-8102 PFC100 PLC (anonymous and username over `None/None` only, no events or history) and against go-opcua demo servers and real MQTT and AMQP brokers for the ECC, reverse connect, discovery, encoding and PubSub features.
